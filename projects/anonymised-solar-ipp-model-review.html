Internal dry run · Not client work · 5 August 2026

TEST-001 was built to expose weaknesses in the delivery process before a paying client could find them.

The previous version over-presented this exercise as a flagship case. That was inaccurate. TEST-001 is an illustrative solar IPP model-review simulation used to test scoping, data classification, issue registers, sensitivities, report writing, attachment checks and human release approval.

Purpose: process validationAsset: illustrative 50 MWac solar IPPNo client or lenderHuman release gate retained

Why it exists

A professional workflow should be tested before it is sold

The dry run took a deliberately incomplete project brief through the same operating sequence intended for live work: qualification, statement of work, data-readiness review, model review, issue classification, sensitivity analysis, report drafting, attachment control and final human approval.

The value of the exercise was not the fictional project return. It was identifying where the process could accidentally turn an assumption into a fact, issue a polished conclusion before the evidence was complete or send the wrong attachment without a final check.

What the dry run exposed

A templated report can look professional while hiding weak provenance. The revised process now requires every material input to carry a source classification and every external message to pass a human review gate.

Controls tested

  • Scope and exclusions agreed before analysis begins.
  • Inputs classified as verified, client-provided, analyst estimate or unresolved.
  • Critical and high-priority findings separated from cosmetic model comments.
  • Base, single-variable and combined downside cases reconciled.
  • Report metrics traced back to the workbook.
  • Recipient, subject, wording and attachments checked before release.

The review logic

The exercise tested whether findings changed the decision

Dry-run findingWhy it was materialControl added or tested
Tariff and yield had no verified sourceThe entire revenue case could be false while the formulas remained correct.Source-classification field and unresolved-information register.
Base DSCR sat on the thresholdA small downside could make debt service unworkable.Combined downside and explicit covenant-headroom commentary.

What is reusable

The process—not the fictional deal

The dry run produced a reusable sequence for real assignments:

  • Turn the brief into a defined decision and SOW.
  • Request the minimum evidence needed to support that decision.
  • Run model integrity, commercial, financing and downside reviews.
  • Issue a prioritised findings register with owner and required action.
  • Write a decision summary that separates facts, assumptions and judgement.
  • Hold external release until Felix has reviewed the message and every attachment.
Clear boundary

TEST-001 is not anonymised client work. It is a partly illustrative internal simulation. It is retained publicly because showing the limitation is more credible than presenting it as a transaction.
